
# 02. Findings & Root Causes

Based on the supporting information, I identified three configuration problems affecting the Billing application's SSO launch.

<BR>

## 1. Audience Validation Failure

**Finding:** The identity provider reports successful sign-ins, but the Billing application rejects them with an `invalid audience` error.

The two sides are configured with different audience identifiers:

- **Identity provider sends:** `https://billing.vendor.example/saml/`
- **Billing application expects:** `https://billing.vendor.example/saml`

**Root cause:** The identifiers differ by a trailing slash. The Billing application requires an exact audience match, so it rejects the SAML assertion.

**Recommended correction:** Update the Identifier (Entity ID) in Microsoft Entra ID to match the value expected by the Billing application.

<BR>

## 2. Identity Mapping Failure

**Finding:** Sam and six colleagues authenticate successfully at the identity provider, but the Billing application cannot match them to their existing accounts.

- **Identity provider sends:** User Principal Name (UPN), such as `sam.okoye@northwindhealth.example`
- **Billing application expects:** Email address, such as `s.okoye@northwindhealth.example`

**Root cause:** The SAML NameID contains the user's UPN, while the application uses email addresses to identify accounts. The naming change introduced in July means these values no longer match for the affected users.

**Recommended correction:** Configure the Billing application's NameID claim in Microsoft Entra ID to send the email address expected by the application, after confirming that the email values are populated and match the existing accounts.

<BR>

## 3. Incorrect Admin Role Assignment

**Finding:** Lena is a Billing Clerk in the `Billing-Readers` group. She signs in successfully but sees the Admin menu, indicating an apparent incorrect Admin role assignment.

**Root cause:** The application assigns the Admin role to users in any group with `Billing` in its name. This includes `Billing-Readers`, not just the intended administrator group.

**Recommended correction:** Replace the broad matching rule with explicit, approved group-to-role mappings. Map `Billing-Readers` to Reader and reserve Admin for the designated administrator group.

---

*These findings are based on the supplied configuration and testing information. The proposed corrections have not yet been implemented or tested.*
