
# 02. Findings & Root Causes

Based on the supporting information, I identified three configuration problems affecting the Billing application's SSO launch.

## 1. Invalid Audience

**Finding:** The identity provider reports successful sign-ins, but the Billing application rejects them with an `invalid audience` error.

The two sides are configured with different audience identifiers:

- **Identity provider sends:** `https://billing.vendor.example/saml/`
- **Billing application expects:** `https://billing.vendor.example/saml`

**Root cause:** The identifiers differ by a trailing slash. The Billing application expects an exact match and therefore rejects the SAML response.

**Recommended correction:** Update the Identifier (Entity ID) in Microsoft Entra ID to match the value expected by the Billing application.

<BR>

## 2. No Matching Account

**Finding:** Sam and six colleagues can authenticate successfully, but the Billing application cannot match them to their accounts.

- **Identity provider sends:** User Principal Name (UPN), such as `sam.okoye@northwindhealth.example`
- **Billing application expects:** Email address, such as `s.okoye@northwindhealth.example`

**Root cause:** The SAML NameID contains the user's UPN, while the application uses email addresses to identify accounts. The naming change introduced in July means these values no longer match for the affected users.

**Recommended correction:** Configure the NameID claim in Microsoft Entra ID to send the email address expected by the Billing application, after confirming those email values are populated and correct.

<BR>

## 3. Incorrect Admin Access

**Finding:** Lena is a Billing Clerk in the `Billing-Readers` group. She signs in successfully but sees the Admin menu.

The Billing application assigns the Admin role to any group whose name contains `Billing`.

**Root cause:** The role-mapping rule is too broad. It can incorrectly classify a reader group as an administrator group.

**Recommended correction:** Change the role-mapping rule in the Billing application so Admin access is assigned only to explicitly authorised administrator groups.

The available information confirms that Lena can see the Admin menu, but not whether she can perform administrative actions. This requires testing.

*These findings are based on the supplied configuration and testing information. The proposed corrections have not yet been implemented or tested.*
