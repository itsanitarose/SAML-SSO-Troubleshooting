

# 04. Digging Deeper

## Trailing Slash: The Cost of a Character

The SAML audience values differed by one character:

| Entra ID Sends | Billing Application Expects |
|---|---|
| `https://billing.vendor.example/saml/` | `https://billing.vendor.example/saml` |

Although these look like URLs, a SAML audience is an identifier, not necessarily a web destination. The application uses it to check whether an assertion was intended for it.

The trailing slash makes the two identifiers different. In this configuration, that difference is enough for the Billing application to reject the assertion, even after Entra ID successfully authenticates the user.

**Why it matters:** Audience validation helps prevent an application from accepting assertions intended for another service. Disabling the check to make sign-in work would weaken that protection.

The vendor temporarily accepted both identifiers during testing. That doesn't automatically make the configuration insecure, but the exception should be removed once both systems use the agreed identifier.

The correction is straightforward: align the audience values, restore the intended validation rules and test sign-in again.

**The lesson:** A one character mismatch can prevent access. The solution is to correct the configuration, not weaken the security check.
