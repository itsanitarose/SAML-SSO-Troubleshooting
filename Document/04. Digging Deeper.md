
## 04. Digging Deeper

### Why Is One Trailing Slash Enough to Break Sign-In?

The SAML audience values differ by a single character:

| Entra ID Sends | Billing Application Expects |
|---|---|
| `https://billing.vendor.example/saml/` | `https://billing.vendor.example/saml` |

<BR>

Although these look like web addresses, the SAML audience is an identifier used to confirm that a sign-in response is intended for the correct application. The values must match exactly.

The extra slash prevents that match, so the application rejects the sign-in rather than accepting a response with an unexpected identifier.

**Users can successfully authenticate with Entra ID but still be denied access to Billing**, even with valid credentials. With the launch approaching, that creates pressure to get sign-in working quickly.

The priority, however, is to correct the mismatch and verify successful sign-in, rather than disable audience validation to meet the deadline.

**The control was working as intended. The configuration needed fixing, not the security standard.**
